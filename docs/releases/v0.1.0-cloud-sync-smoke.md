- Date/time: 2026-05-02

- Firestore path: `users/{uid}/state/progress`

## Implementation Status

- Google Auth is used for the Firebase `uid`.
- Firestore is used as the user-owned cloud progress store.
- LocalStorage remains the signed-out and offline fallback.
- Firestore listener uses `onSnapshot` for live remote updates.
- Local progress writes dispatch a browser event and are debounced before upload.
- Remote snapshots are written back to localStorage and refresh the active screen.

## Synced Domains

- Trainer progress: attempts, correct answers, mistakes by item, daily counters.
- 12-day intensive progress: selected day, completed task ids, notes, timestamps.
- Grammar progress: attempts, correct answers, mistakes by task.
- Writing progress: drafts and checked criteria.
- Speaking progress: completed prompts.
- Reading progress: completed tasks and best scores.
- Listening progress: completed tasks and best scores.
- Mini mock result: latest result.

## Merge Rules

- Trainer and grammar numeric counters use max values to avoid replacing advanced progress with older local data.
- Mistake maps use max count per item/task.
- Checklist-style arrays use union.
- Note/draft records prefer the newer `updatedAt` when available.
- Latest mock result prefers the newer `completedAt`.
- Empty local values do not erase non-empty cloud values.
- Empty cloud values do not erase non-empty local values.

## Firestore Rules

Rules were deployed to `device-streaming-c9d158cc` with this ownership model:

```text
users/{userId}/{document=**}
allow read, write: if request.auth != null && request.auth.uid == userId;
```

## Cross-Device Proof

Status: PARTIAL in automation.

The implementation requires a real Google account session in two browser contexts or devices:

1. Sign in on desktop.
2. Answer two trainer questions.
3. Sign in on phone with the same Google account.
4. Confirm trainer progress appears.
5. Update progress on phone.
6. Confirm desktop updates through the Firestore listener.

This final real-device check still must be performed manually before claiming public cross-device sync PASS.

## Limitations

- Writes are debounced, not conflict-resolved with a full UI.
- Offline queue is limited to localStorage fallback; sync resumes on the next online progress change or login sync.
- Cloud sync stores learning progress only, not private profile data.
